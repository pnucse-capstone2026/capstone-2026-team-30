# 1. 기술 스택 및 아키텍처 선정 (Next.js, NestJS, TypeScript, Monorepo)

## Status

Accepted

## Context

본 프로젝트는 쿠버네티스 환경 내 Kyverno 거버넌스 정책을 모니터링하고 관리하는 플랫폼을 구축하는 것을 목표로 합니다.
기술 스택 및 아키텍처를 결정하는 과정에서 다음과 같은 인적 구성과 기술적 제약 사항을 고려했습니다

1. 프론트엔드 생산성 극대화:
   * 프론트엔드의 경우 AI 에이전트가 강세를 보이는 분야이므로, 이를 적극 활용하는 개발 방식(Agentic Coding)에 특화된 도구 구성을 시도했습니다
   * 이에 따라 정적 타입 분석 및 AI 기반 코드 완성이 매우 강력한 것으로 잘 알려진 TypeScript를 주 언어로 채택하였으며, 더불어 에이전트가 마크업을 확장하기 용이한 shadcn/ui 라이브러리를 선정했습니다

2. 백엔드 프레임워크 선정:
   * 백엔드 담당 팀원은 Java Spring Boot 프레임워크 경험을 가지고 있습니다
   * 프론트엔드와 백엔드가 같은 데이터 모델이나 타입 정보를 공유하면 소통 비용을 줄일 수 있습니다. 이를 해결하기 위해 백엔드 언어로도 TypeScript를 채택하고, Spring Boot의 의존성 주입(DI) 등 아키텍처 구조와 가장 유사하여 Spring Boot 엔지니어가 쉽게 학습하고 구조적으로 개발할 수 있는 NestJS 프레임워크를 선정했습니다
   * 이를 통해 단일 모노레포 구조 안에서 프론트엔드와 백엔드가 데이터 모델 타입을 온전히 공유할 수 있는 생산성을 확보하고자 했습니다

3. 쿠버네티스 연동의 용이성:
   * 본 플랫폼의 핵심 비즈니스 로직은 쿠버네티스 API와의 연동을 필요로 합니다
   * 쿠버네티스 공식 JavaScript/TypeScript SDK인 @kubernetes/client-node 패키지를 사용할 경우, Node.js 기반 런타임 환경인 NestJS에서 쿠버네티스 자원 관리 로직을 편리하게 구현할 수 있다는 이점이 있습니다

## Decision

1. 모노레포 아키텍처 채택:
   * 프론트엔드, 백엔드, 공통 패키지를 단일 Git 저장소에서 효율적으로 관리하고 의존성을 최적화하기 위해 pnpm workspaces 기반의 모노레포를 도입합니다
2. 프론트엔드 기술 구성:
   * UI 대시보드 애플리케이션(apps/frontend)은 Next.js 15(React 19) 및 TypeScript를 기반으로 구축합니다
   * 개발 효율성과 디자인 일관성을 확보하고 AI 에이전트 친화적인 개발을 지원하기 위해 shadcn/ui 및 Tailwind CSS를 도입합니다
3. 백엔드 기술 구성:
   * API 서버 애플리케이션(apps/backend)은 TypeScript 기반의 NestJS 11 프레임워크를 적용합니다
   * 데이터베이스 접근 및 관리를 위해 데이터베이스 스키마에서 타입을 즉시 동기화해 주는 Prisma ORM(PostgreSQL)을 채택합니다<br>
   `(See also : 0002-database-access-technology)`
   * 쿠버네티스 API 연동을 위해 공식 @kubernetes/client-node SDK를 도입합니다
4. 공유 모듈 패키지 운영:
   * 프론트엔드와 백엔드 간에 동일한 타입 선언과 유틸리티 코드를 이중 작성 없이 즉각 공유할 수 있도록 packages/shared 공통 패키지를 구성하여 함께 빌드하고 활용합니다.

## Consequences

* 얻을 수 있는 이점:
  * 개발 생산성 및 AI 협업 효율 향상: TypeScript의 강력한 타입 지원과 shadcn/ui의 컴포넌트 구조 덕분에 AI 에이전트 코딩(Vibe Coding)을 활용한 UI 구현 속도가 크게 개선될 것으로 예상됩니다.
  * 프론트-백엔드 간 타입 무결성 보장: 백엔드의 데이터 스키마와 공통 응답 타입을 모노레포 내 공통 패키지를 통해 프론트엔드로 즉시 노출함으로써, API 명세 변경 시 발생할 수 있는 데이터 타입 불일치 버그를 개발 시점에 차단합니다.
  * 학습 및 개발 장벽 완화: Spring Boot 경험이 있는 백엔드 개발자가 NestJS의 유사한 의존성 주입(DI) 및 모듈화 설계를 통해 빠르게 백엔드 API를 개발할 수 있으며, 단일 언어(TypeScript) 사용으로 풀스택 협업 및 코드 리뷰가 용이해집니다.
  * 안정적인 쿠버네티스 통신: 공식 SDK 활용을 통해 쿠버네티스 클러스터 자원 정보 수집 및 정책 관리를 단순하고 직관적인 코드로 빠르게 연동할 수 있습니다.

* 감수해야 할 제약 사항:
  * 모노레포 의존성 및 빌드 제약: pnpm workspace 구조에 익숙하지 않은 경우, 패키지 간 내부 참조 링크 및 의존성 업데이트 시 필요한 workspaces 개념에 대해 초기 학습이 필요할 수 있습니다
  * 단일 언어 종속성: 모든 구조가 Node.js 및 TypeScript에 의존하므로, 추후 다른 런타임 플랫폼으로의 개별 전환이 필요한 경우 아키텍처 수준의 리팩토링 비용이 크게 증가할 수 있습니다.
