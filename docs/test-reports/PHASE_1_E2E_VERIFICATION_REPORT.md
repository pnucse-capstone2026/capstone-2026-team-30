## 3. 시나리오별 E2E 검증 결과

### 3.1. 시나리오 1: 정상 매니페스트 통과 (Clean Pass)

* **테스트 목적**: 플랫폼 거버넌스 및 보안 정책을 완벽히 준수하는 매니페스트 제출 시 100% 결정론적 통과 여부 검증
* **검증 매니페스트**: 표준 라벨(`app.kubernetes.io/name`, `team`) 및 공인 ECR 이미지(`public.ecr.aws/...`), 비특권 모드로 작성된 Nginx Deployment
* **입력 Payload**:
  ```json
  {
    "repository": "acme-corp/payment-service",
    "pullNumber": 101,
    "commitSha": "a1b2c3d4e5f6789012345678901234567890abcd",
    "clusterId": "default",
    "targetNamespace": "default",
    "manifestYaml": "apiVersion: apps/v1\nkind: Deployment\n..."
  }
  ```
* **응답 결과 (HTTP 201 Created)**:
  ```json
  {
    "valid": true,
    "dryRunPassed": true,
    "blocked": false,
    "totalResources": 1,
    "blockedCount": 0,
    "status": "PASSED",
    "commentMarkdown": "## 🛡️ Kyverno Governance Gate: ✅ PASSED\n\n모든 쿠버네티스 리소스 매니페스트가 플랫폼 보안 및 거버넌스 정책을 정상적으로 통과했습니다.\n\n* **검증 리소스 수**: 1개\n* **타겟 네임스페이스**: `default`\n* **타겟 클러스터**: `default`\n* **검증 방식**: Server-Side Dry-Run (`dryRun: ['All']`)\n\n---\n*Generated by Kyverno Governance Platform Shift-Left Gate.*",
    "commitStatus": "skipped",
    "violations": []
  }
  ```
* **검증 통과 항목**:
  - [x] HTTP 201 응답 및 `valid: true`, `dryRunPassed: true`
  - [x] `blocked: false`, `blockedCount: 0`, `violations: []`
  - [x] PR Bot 마크다운 코멘트에 `🛡️ Kyverno Governance Gate: ✅ PASSED` 배지 포함

### 3.2. 시나리오 2: 정책 위반 및 AI Self-Correction 교정 통과 (Self-Correction Success)

* **테스트 목적**: 필수 식별 라벨이 누락된 매니페스트 제출 시, 1차 Dry-Run 거부 -> AI 수정안 생성 -> 2차 Dry-Run 재검증 성공으로 이어지는 Self-Correction Loop 무결성 검증
* **동작 흐름**:
  1. 1차 Server-Side Dry-Run 시 Kyverno `require-labels` 정책에 의해 `403 Forbidden` 발생.
  2. `executeSelfCorrectionLoop` 진입하여 에러 메시지 및 원본 매니페스트를 분석.
  3. 누락된 `app.kubernetes.io/name` 및 `team: platform` 라벨이 주입된 교정본 매니페스트 생성.
  4. 교정본으로 2차 Server-Side Dry-Run 재검증 수행 -> 성공 (`valid: true`).
* **응답 결과 (HTTP 201 Created)**:
  ```json
  {
    "valid": false,
    "dryRunPassed": false,
    "blocked": true,
    "totalResources": 1,
    "blockedCount": 1,
    "status": "BLOCKED",
    "selfCorrectionResult": {
      "corrected": true,
      "attempts": 1,
      "suggestedPatch": "apiVersion: apps/v1\nkind: Deployment\nmetadata:\n  name: e2e-nginx-missing-labels\n  namespace: default\n  labels:\n    app.kubernetes.io/name: e2e-nginx-missing-labels\n    team: platform\n..."
    },
    "commentMarkdown": "... ### 🤖 AI 자동 교정 제안 `[AI Self-Correction Passed]`\n> **Server-Side Dry-Run 검증 통과**: 아래 제안된 매니페스트는 클러스터의 Kyverno 정책을 완벽히 준수하도록 자체 재검증되었습니다.\n\n```suggestion\napiVersion: apps/v1\nkind: Deployment\n..."
  }
  ```
* **검증 통과 항목**:
  - [x] 1차 원본 매니페스트 차단 (`blocked: true`, `blockedCount: 1`)
  - [x] AI 자가 교정 및 2차 Dry-Run 재검증 통과 (`selfCorrectionResult.corrected: true`)
  - [x] 코멘트 본문에 `[AI Self-Correction Passed]` 배지 및 GitHub `suggestion` 코드블록 포함

### 3.3. 시나리오 3: 치명적 보안 위반 및 Safe Guidance 폴백 (Safe Fallback & Deep-link)

* **테스트 목적**: 보안상 위험한 특권 컨테이너(`securityContext.privileged: true`) 요청 시 임의 자동 수정을 방지하고, 안전 권장 조치 가이드와 플랫폼 정책 예외(PolicyException) 신청 딥링크를 정상 제공하는지 검증
* **동작 흐름**:
  1. 1차 Server-Side Dry-Run 시 Kyverno `disallow-privileged` 정책에 의해 배포 차단.
  2. 특권 컨테이너 권한 침해에 대해 AI 시스템이 안전 지침에 따라 임의 자동 수정안을 배제 (`selfCorrectionResult.corrected: false`).
  3. PR Bot 코멘트에 `[AI Self-Correction Incomplete / Safe Guidance]` 마크다운 생성.
  4. 해당 클러스터, 네임스페이스, 정책명, 리소스명이 자동 입력되는 플랫폼 예외 신청 딥링크 생성.
* **응답 결과 (HTTP 201 Created)**:
  ```json
  {
    "valid": false,
    "dryRunPassed": false,
    "blocked": true,
    "status": "BLOCKED",
    "selfCorrectionResult": {
      "corrected": false,
      "attempts": 1,
      "guidance": "nginx-privileged 배포가 특권 컨테이너 실행을 허용하지 않는 보안 정책 때문에 거부되었습니다..."
    },
    "exceptionDeepLink": "http://localhost:3000/exceptions/new?repo=acme-corp%2Fpayment-service&pr=103&cluster=default&clusterId=default&namespace=default&policy=kyverno-policy&policyName=kyverno-policy&kind=Deployment&resource=e2e-nginx-privileged&resourceName=e2e-nginx-privileged",
    "commentMarkdown": "... ### 🤖 AI 권장 조치 가이드 (Manual Review Required) `[AI Self-Correction Incomplete / Safe Guidance]`\n<!-- AI Auto-fix could not pass deterministic policy dry-run verification -->\n# 권장 조치 가이드\n...\n### 📝 정책 예외(Policy Exception) 신청\n👉 [**플랫폼 정책 예외 신청하기 (Auto-filled Link)**](http://localhost:3000/exceptions/new?...)"
  }
  ```
* **검증 통과 항목**:
  - [x] 보안상 자동 교정 불가 판단 (`selfCorrectionResult.corrected: false`)
  - [x] 코멘트 본문에 `[AI Self-Correction Incomplete / Safe Guidance]` 배지 및 조치 가이드 마크다운 생성
  - [x] 플랫폼 정책 예외 신청 딥링크에 `clusterId`, `policyName`, `resourceName` 파라미터 자동 바인딩 확인

### 3.4. 시나리오 4: CI/CD 이중 인증 가드 (Dual Authentication Guard)

* **테스트 목적**: 웹 대시보드(JWT) 외에 GitHub Actions 등 CI/CD 파이프라인에서 시크릿 토큰(`X-CI-Token`) 기반으로 안전하게 게이트웨이를 호출하고, 인가되지 않은 요청을 엄격히 차단하는지 검증
* **검증 결과**:
  | 케이스 | 요청 헤더 | 기대 상태 코드 | 실제 응답 | 결과 |
  | :--- | :--- | :---: | :---: | :---: |
  | **정상 토큰** | `X-CI-Token: test-ci-token-secret` | `201 Created` | `201` | **PASS** |
  | **잘못된 토큰** | `X-CI-Token: invalid-wrong-token-value` | `401 Unauthorized` | `401` | **PASS** |
  | **헤더 누락** | (인증 헤더 없음) | `401 Unauthorized` | `401` | **PASS** |
* **검증 통과 항목**:
  - [x] 타이밍 공격 방지 상수 시간 비교(`crypto.timingSafeEqual`) 동작 확인
  - [x] 인증 성공 시 `ci-bot` 가상 사용자 컨텍스트 정상 주입
  - [x] 유효하지 않거나 누락된 토큰 요청 즉각 차단 (HTTP 401)

## 5. 결론 및 종합 평가

1. **결정론적 Server-Side Dry-Run 보장**:
   클라이언트 측 단순 린팅이 아닌, 실제 타겟 클러스터의 Kyverno 어드미션 웹훅 엔진(`dryRun: ['All']`)을 통해 실제 배포 시점과 100% 동일한 어드미션 차단 및 검증 결과를 도출함을 확인하였습니다.
2. **환각(Hallucination) 없는 AI 자가 교정 루프**:
   AI가 제안한 수정안을 개발자에게 전달하기 전 서버사이드 드라이런으로 재검증하여, 재검증을 통과한 유효한 YAML만 GitHub `suggestion` 코드블록으로 제공함을 입증하였습니다.
3. **치명적 보안 위반 안전 폴백**:
   `privileged: true`와 같은 치명적인 권한 요청에 대해 무리한 자동 수정을 방지하고, 안전 권장 조치 가이드와 정책 예외 딥링크로 연계하여 보안 거버넌스 무결성을 유지함을 검증하였습니다.
4. **엔터프라이즈 CI/CD 파이프라인 연동 준비 완료**:
   `X-CI-Token` 이중 인증을 통해 GitHub Actions, GitLab CI 등 다양한 외부 CI 시스템과 즉시 통합 가능한 수준의 완성도를 확보하였습니다.
